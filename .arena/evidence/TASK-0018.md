## What was wrong

`cleanup.yml` checked out `main` with `fetch-depth: 1` and `cleanup_runner.py` verified `merge_commit_sha` with
`git cat-file -t`. When another PR merged in between, the merge commit sits behind the shallow boundary; the
runner's retry `git fetch origin main` cannot reach it either (same boundary) and the job failed on `main`.
Second defect: the `git push origin --delete` was nested inside the Supabase "task found" block and the only
protected names were `main`/`master`, so an `arena/agent-NN` workspace or `arena-manager` as PR head would
have been deleted (DEC-0017 makes agent branches permanent).

## What changed

`tools/orchestration/cleanup_runner.py` (rewritten, same CLI: `--branch --merge-sha --pr --skip-tests`; new
`--remote`, `--main-branch`, `--dry-run`; `main()` returns the exit code):
- `ensure_merge_commit_on_main`: the commit must exist locally **and** be an ancestor of
  `refs/remotes/<remote>/main`. Recovery ladder when it is not: fetch main (explicit refspec) → if shallow,
  `--deepen=50` then `--deepen=500` → fetch the SHA explicitly → if still shallow, `--unshallow`. Only when all of
  that fails does it abort, distinguishing "does not exist on origin" from "exists but is not an ancestor of main
  (main may have been rewritten)". Nothing is deleted before this proof.
- `is_permanent_branch`: `main`, `master`, `arena-manager` and `^arena/agent-\d+$` are never deleted, whatever
  the PR head was; the deletion step returns `PROTECTED`, prints a `::warning::` annotation and the job exits 0.
  `arena/manager/<slice>` (Slice PR heads) and legacy `arena/agent-01/TASK-0001` stay deletable.
- Already-gone head: `git ls-remote --exit-code --heads` before the push (exit 2 = no such ref → `ALREADY_GONE`,
  exit 0), plus GitHub's `remote ref does not exist` on a lost race → `ALREADY_GONE`, exit 0. Any other refusal
  is a clear error (exit 1).
- Branch deletion no longer depends on the Supabase control plane. Under DEC-0017 git is the task authority, so
  the legacy MERGING → POST_MERGE_VERIFY → CLEANUP → COMPLETED mirror is best effort: unconfigured → skipped,
  no matching task → skipped, `ALREADY_COMPLETED` → continue idempotently, any exception → logged, cleanup
  continues. `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` are read from the environment into the client and
  never printed; `git` never prompts (`GIT_TERMINAL_PROMPT=0`); every subprocess line that is echoed passes
  through `redact()` (GitHub tokens, PATs, JWTs, Supabase keys, `user:token@` URLs).
- Inputs are validated before any git call (`git check-ref-format --branch`, `refs/heads/` prefix stripped,
  SHA must be 7–40 hex).

`.github/workflows/cleanup.yml`:
- `fetch-depth: 0` (a complete history keeps the ancestry check conclusive; the runner would also cope with a
  shallow checkout). The repository is ~36 MB, and the self-hosted workspace persists, so this is a one-time cost.
- `permissions: contents: write` (explicit least privilege for the ref deletion).
- Env values quoted; `--skip-tests` because the previous step already runs `cargo check --workspace` and
  `cargo test -p n8n-workflow` on the same checkout (previously they ran twice).
- Unchanged: trigger, `if: merged == true`, `runs-on: [ self-hosted, linux, x64, rust-build, n8n-rust ]`, and the
  secret env references `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `GITHUB_TOKEN`.

`tools/orchestration/test_cleanup_runner.py` — 28 tests, no network / secrets / cargo. "Remotes" are bare
repositories in a temp dir reached through `file://` so `--depth 1` clones behave like `fetch-depth: 1`;
`HOME` is a scratch dir; the control plane is an in-memory stub.
