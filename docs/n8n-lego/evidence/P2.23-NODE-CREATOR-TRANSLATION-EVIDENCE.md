`node:creator:create | node:creator:translate | node:creator:validate | node:read`;

### Creation and identity

`create(definition, identity)` derives `contract = nodeId@version`, freezes and returns a
`CANDIDATE` record (`recordId`, `state`, `candidate`, `reference/approval/validation` all
null initially). Identity primitive: `creationMode ∈ {HUMAN, NODE}`, `creatorKind =
'node-creator'`, `sourceKind ∈ {manual, imported, translated}` — creation mode is provenance
and (for NODE) a stricter approval requirement, never a validation bypass. Structural errors
throw `NodeCreatorError` / `lego.contract_violation`; bounds are deterministic refusals
(`CREATOR_LIMITS`: depth 16, schema nodes 256, candidate keys 64, artifact requirements 8,
name 128, description 512, source bytes 65536). Sensitive values (credential-shaped text,
secret-shaped creatorIds) are refused at the door.

### One pipeline, one authority

`validate()` runs creator-contract checks → `canPort` from `node.portability@1.0.0`
(imported; the module contains no re-implementation and no alternative checker) → approval
gate. Result states: not required → `VALID`; required → `APPROVAL_REQUIRED` (opens an
explicit P2.19 approval with actor, risk, scope `node-registry:<id>`, action
`node.create:<contract>`); granted → `APPROVED` → seals a reference →
`PUBLISHED_REFERENCE`; denied/expired/unknown-approval/scope-mismatch → `REJECTED` with
reason `approval-not-granted` (fail-closed); still requested → stays
`APPROVAL_REQUIRED`. Terminal `REJECTED`/`PUBLISHED_REFERENCE` re-validate idempotently.
`APPROVAL_POLICY` is derived from the P2.22 `CLASS_DECLARATION_RULES` (four
authority-bearing classes) plus NODE creation mode — `requiresApproval`/`approvalRiskFor`
are pure policy-table reads; policy objects are frozen.

### The reference is not authority

After approval the record is sealed into a P2.19 artifact-registry record: kind `file`,
storageRef `node.definition/<nodeId>@<version>`, checksum `artifactContentDigest` of the
canonical candidate core, content behind the opaque reference. `reference.meaning` states
plainly that a publishable reference exists and that the creator holds no publishing
authority. Denied/ghost approvals never produce a reference. `securityProfile` key is
**omitted when null** so the shape still satisfies the P2.22 contract unchanged.

### Translation (deterministic, offline, fail-closed)

`translate({sourceRuntime, sourceReference, source}, identity)` maps a closed source
vocabulary onto the same candidate shape; success → `CANDIDATE` with
`translationProvenance` (translator `node.creator@1.0.0`, sourceRuntime, sourceDigest
`sha256:…`) and `sourceKind` stamped `translated`; `recordId` is content-addressed, so
identical input yields byte-identical output (§32). Refusals are canonical and persisted:
`lossy-source-field` (token/credentials/apiKey/secret/…), `unknown-source-construct`
(unknown top-level keys), `unknown-language-marker`, `schema-unsupported` /
`schema-lossy` from the P2.22 family — never a silent drop, never a partial candidate.
Forbidden field list includes webhookUrl-style constructs in tests; nothing ever imports
network/child-process/timers or provider/model names.
