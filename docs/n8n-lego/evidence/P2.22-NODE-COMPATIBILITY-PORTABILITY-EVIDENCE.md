## The foundation (what shipped)

### §6 Portability classes (canonical seven)

`PURE · API · NETWORK · FILESYSTEM · NATIVE_PROCESS · ENVIRONMENT_SPECIFIC · REMOTE_BRIDGE` —
singular words; competing synonyms (`networked`, `remote-only`, `server`, `local-fs`,
`native-host`) are banned by test against the module source.

### §7 Portability model (machine-readable, never free text)

`node = { nodeId, contract, portability { class, transport?, runtimeRequirements?,
environmentRequirements? }, requiredCapabilities, requiredPermissions, schemas { input, output },
artifactRequirements?, securityProfile? }` — structural errors throw
`NodePortabilityError`/`lego.contract_violation`; semantic answers come back from a closed
reason set.

### §8 Language-neutral schema subset

SUPPORTED: `scalar · object · array · nullable · enum · required · optional · constraints ·
default · additionalProperties`. LOSSY: `format`. UNSUPPORTED: `pattern · union · reference` +
every keyword outside the subset (unknown keyword → `schema-unsupported` with detail).
Invalid defaults / non-boolean `additionalProperties` / missing `type` / array without `items` /
`required` naming an undeclared property → `schema-unsupported` reason or contract throw —
**never a silent coercion.**

### §9 Round-trip rule

`roundTrip(schema, target)`: canonical (key-sorted, values untouched) → per-target tagged
representation → decode → canonical again; `roundTrip == canonical` for the portable subset on
every non-UNSUPPORTED target (tested feature × target). LOSSY/UNSUPPORTED return
`equal:false` with `schema-lossy`/`schema-unsupported` and **no half-converted output**
(`canonical:null`).

### §10 Compatibility report — five axes, never one boolean

`compatibility: { contract, schema, runtime, portability, environment }` +
`overall ∈ {portable, conditional, not-portable}` + `reason = <first failing axis>-incompatible`
(canonical axis order). Worked example proven by test: contract compatible, schema compatible,
runtime incompatible → `overall=not-portable, reason=runtime-incompatible`.

### §11 Runtime selection policy

Criteria in order: `security · performance · portability · compatibility · capability-requirements ·
environment-constraints`. No language target is preselected (source-scanned for
`rust is/always`, `javascript is/always`). Filter = `canPort` + security profile; order =
SUPPORTED before CONDITIONAL, declared `performanceRank` next, canonical enumeration last
(documented as enumeration, not favor). Every rejection carries its axis reason.

### §12 Runtime matrix (machine-readable)

7 × 4 cells, each `SUPPORTED | UNSUPPORTED | CONDITIONAL` with closed condition codes
(`transport-context`, `remote-authority`, `capability-host`, `environment-context`).
Documented example row holds: PURE = JS/WASM/RUST supported, REMOTE conditional.
Honesty rules: SUPPORTED cells carry zero hidden conditions; CONDITIONAL cells state ≥1;
FILESYSTEM/WASM and NATIVE_PROCESS/WASM are UNSUPPORTED; REMOTE_BRIDGE is UNSUPPORTED on all
local-only runtimes.

### §13/§14 Capability/permission linkage + security model

Portability **grants nothing**: the answer object's key set is asserted (no
`granted/authorized/credential/approval` fields). Class rules: PURE forbids declaring any
capability/permission/environment/transport (`declaration-conflict`); NETWORK/FILESYSTEM/
NATIVE_PROCESS/REMOTE_BRIDGE require ≥1 capability **and** ≥1 permission from their own closed
category (`PERMISSION_CATEGORIES`: network = `webhook:`/`realtime:`, filesystem = `storage:`,
process = `worker:`/`runtime:`, remote = `lego:invoke`) — a filesystem word never authorizes a
network node; ENVIRONMENT_SPECIFIC requires explicit `environmentRequirements`
(`missing-environment`); REMOTE_BRIDGE requires declared `transport`.
Permissions themselves come from the capability/approval system (P2.19) — this module only
classifies.

### §15/§16 Validator + fail-closed

`canPort(node, targetRuntime, context?)` runs declaration rules → schema subset → matrix/conditions
→ round-trip → environment → security, all against closed tables. Refusals (all covered by tests):
`unknown-runtime · unknown-portability-class · unknown-capability · unknown-permission ·
missing-permission · missing-capability · missing-environment · environment-mismatch ·
transport-mismatch · capability-host-missing · security-mismatch · schema-unsupported ·
schema-lossy · target-unsupported · declaration-conflict · round-trip-failed` — each maps to an
axis (`REASON_AXIS`); no `unknown → assume portable` path exists (table-driven tests + closed-set
round-trip over every answer in the suite).

### §25/§26 Performance & cache

O(1) lookups over frozen maps; the capability/permission vocabulary loads **once** from the
domain registry (single source of truth) into Sets — no filesystem scan per invocation, no
network, no subprocess, no package installation. There is **no cache layer at all**: answers are
pure functions of (declaration, target, context), so permission/capability changes in the
manifest are observed on the next call by construction — nothing caches `portable=true`.

### §27 Error model

No new error codes: structural failures use published `lego.contract_violation`
(`errors.contract.json` stays 1.2.0). Semantic refusals are result reasons from the exported
closed set — not free-text.

### §22 Differential testing

`CANONICAL_FIXTURES` (JS/WASM/RUST_NATIVE) + `DIFFERENTIAL_FACETS = [input, outputSchema, errors,
artifactMetadata, sideEffectDeclaration]` + `compareImplementations` — compares declared facets
only; hidden implementation details and byte-identical executables are out of scope by design.
Positive fixtures prove equivalence; a mutated side-effect declaration is reported as a single
mismatch by facet and target pair.
