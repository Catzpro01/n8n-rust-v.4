## §12–§14 — translation and seam rules

- `RUNTIME_LIFECYCLE_TRANSLATION` maps the official runtime vocabulary onto **canonical machine
  operations only**: `connect→[]`, `start→[create,prepare,start]`, `send→[step]`,
  `pause→[pause]`, `resume→[resume]`, `cancel→[cancel]`, `status→[status]`, `artifact→[artifact]`,
  `disconnect→[]`, `stream→null` (declared-unsupported). Targets are verified ⊆
  `AGENT_MACHINE_OPERATIONS` at module load — **no second lifecycle vocabulary**.
- Adapter ≠ new agent machine: no task/graph/budget/permission/approval/event vocabulary of its own;
  canonical `AGENT_EVENT_TYPES` only on `forwardEvent`.
- remote ≠ external (locality is its own axis: `in-process|local-process|local-network|remote`),
  MCP ≠ external, transport ≠ locality (§14 preserved in the capability `transport` block).

## §25–§26 — EXTERNAL fail-closed chain

Eligibility order (reasons are explicit, stable strings):
`unknown-provider → unsupported-contract → unknown-executor-kind → unsupported-executor-kind
→ unsupported-operation → missing-capability → unavailable → eligible`.

- `register` rejects: duplicate id, capacity (`maxRuntimes`=16), contract ≠
  `ai.agent-runtime@1.0.0`, capability outside the FE-quoted vocabulary, non-canonical locality or
  availability, executorKinds without `EXTERNAL`, secret-shaped strings — every failure
  `lego.contract_violation` or `lego.unavailable` with no eligibility.
- `provider.supports(kind)`: `IN_MEMORY → true`; `EXTERNAL → registry.liveEligibility(providerId)`
  (**live re-check, not a cached true**); anything else → `false` (default-closed).
  Unregistered/unavailable EXTERNAL therefore falls through the unchanged P2.16 gate to
  `lego.unavailable` — P2.16 code and its 83 assertions untouched (§11).
- No wildcard, no discovery, no trust-by-name: a declared provider is not enough — the adapter must
  be registered AND the contract supported AND capabilities declared AND locality canonical.

## §17–§24 — deterministic harness

`createAdapterHarness({now, machineId, responses, limits})`:

- injectable clock (`now()`), id factory (`machineId()`), response sequence (FIFO), fixed limits;
  **no timers, no sleep, no Math.random, no wall clock** — the only import beyond the seam is
  `node:crypto` randomUUID inside the factory default (tests inject their own).
- scenario shape: `{scenarioId, initial, operations, expected}`; expected keys:
  `state, events, errors, timing, lifecycle, retryAttempts, outboxAccepted, dropped, translated,
  cancellations` — errors are CAPTURED (not thrown) so fail-closed runs stay inspectable (§21).
- Required scenarios all present and green: lifecycle, cancel, deadline, backpressure, retry,
  failure-isolation, events, correlation, causation, cancellation-propagation (§21),
  plus determinism (re-run byte-identical) and closed-world (no shell/fs/subprocess/model/mcp/approval
  imports) — 38/38.
- **Deadline (§23):** machine created at T0, `advance(T0+2000)` against `maxElapsedMs=1000` →
  canonical transition refusal with zero real time elapsed; deadline is never extended by the clock.
- **Backpressure (§24):** outbox bounded at `maxPendingEvents=8`; the 9th canonical event returns
  `{accepted:false, reason:'backpressure'}`; no unbounded queue/promise/event growth anywhere in
  the module (bounded pull loop, bounded retries, bounded map sizes via `ADAPTER_LIMITS`).
- **Cancel (§22):** idempotent, bounded — second cancel leaves version/events unchanged;
  `signalCancellation` returns `{propagated:false, reason}` when no runtime seam exists rather
  than inventing propagation.
- **Correlation/causation (§20):** forwarded events carry `correlationId`/`causationId` from the
  scenario (machineId of the source, operation index) — opaque ids only.

### §38 decision (honest note)

The P2.16 contract suite is executed **unchanged, through the adapter, as a differential replay**:
`createAgentMachineManager({provider: adapterProvider})` — the seam the locked
`agent-machine.json#provider.replacement` declares — replays a fixed operation sequence and the
default host replays the identical sequence; both sides are compared with `deepStrictEqual`
(lifecycles, errors, error messages, public record fields, `last`), and the pinned messages
(waiting-resume refusal, `storage.conflict`, `storage.not_found`, `lego.contract_violation`) are
asserted to be byte-identical on both sides. The original P2.16 suite continues to run **as-is**
(83/83: `lego-agent-machine` 57 + `lego-agent-machine-runtime` 26) — no copy-paste-modified fork,
no loader hook (a loader/monkey-patch approach was rejected: it would break P2.16's explicit
`supports('EXTERNAL') === false` assertion and rely on experimental loader flags in the official
runner). Differential replay proves same tests, same semantics; both artifacts are cited here.

   subject id now refreshed on **every** operation outcome.

   tokens (`ghp_…`) could pass → secret scan runs **first** (closes the gap, §41).
