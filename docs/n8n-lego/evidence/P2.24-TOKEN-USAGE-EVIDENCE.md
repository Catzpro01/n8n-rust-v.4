## §4 Implementation

`apps/n8n-lego/src/lego/token-usage.mjs` — **zero imports** (no builtin, no cross-domain
reach; §9 default satisfied in full), `now`/`newId` **required** at factory creation (§8 —
refuses to exist without injection, mirroring P2.19/P2.23), frozen records, bounded store
(`USAGE_LIMITS.maxRecords = 4096`), one error family (`TokenUsageError.code =
'lego.contract_violation'` — errors contract 1.2.0 untouched).

- `record(entry)` — closed shape (`TOKEN_USAGE_FIELDS`, 11 fields); idempotent on
  `requestId`: identical retry returns the byte-identical record and mints **no new id**
  (no counter advances on replay); same identity + different payload → `request-id-reuse`
  refusal, never an overwrite.
- `query(filter)` — exact-match filters, frozen insertion order, deterministic.
- `budget({scopeLevel, scopeRef, kind, limit})` — derivation rules: no records →
  `unavailable` (empty ≠ zero); any unavailable member → whole total `unavailable` (a hole
  is never summed); any estimated member → `estimated` (worst certainty wins); all reported
  → `reported`. `over`/`remaining` exist only when `used` is derivable — unavailable never
  means "within budget".
- `calculateCost({usage, pricingBasis, rule})` — pure, offline, **no pricing tables in the
  module**: reported usage + handed pricing basis + declared rule (`linear-input-output`) →
  `calculated`; missing pricing (or a missing rate) → `unavailable` (`pricing-unavailable`),
  never a guess; an estimated input → cost labelled `estimated`, never actual; unavailable
  usage → `unavailable`; unknown rule → contract violation; `message` is refused as a cost
  input (it is a subset of `modelInput` — accepting both would double-count by construction);
  a *declared* 0 rate is a known price (free model), distinct from a missing rate.

## §5 Honest accounting semantics

Minimal record: **value · kind · source · certainty** (+ scopeLevel/scopeRef/requestId/unit/
estimator/createdAt). Vocabulary:

- `TOKEN_KINDS = [message, modelInput, output]` — quoted byte-for-byte from the P2.13
  reference scenario; provider spellings (inputTokens, promptTokens, …) are asserted absent
  from the module and from the kinds list; provider-specific terms map only through a
  documented mapping;
- `USAGE_STATUSES = [reported, estimated, unavailable]` — `reported` only when the source
  supplied the number; `estimated` only with a named, bounded estimator travelling with the
  value (an estimate without a method is not recordable); `unavailable` is `null` and a
  record asserting `value: 0, status: unavailable` is a contract violation — **missing is
  never zero**, in `record`, in `query` results and in `budget` totals alike;
- `USAGE_SCOPES = [call, run, session]` — the three granularities XA-17 asks about, all
  three queryable (test).

## §6 Security / privacy

No prompt, completion, reasoning, credential, authorization or API-key field can enter a
record: forbidden names are refused **by name** and the refusal message never echoes the
value; the closed shape refuses any unknown field. String identifiers (`requestId`,
`scopeRef`, `source`, `estimator`) are bounded and scanned against `SENSITIVE_USAGE_RE` —
full canonical credential shapes (`ghp_`+36, `github_pat_`, `sk-`, `Bearer …`), **not bare
prefixes**: a regex literal in the source and a truncated prefix are asserted *not* to match
(the P2.23 detector false-positive lesson applied). Bearer-shaped fixtures are refused by
the identifier grammar itself. Static source assertions: no provider names, no live token
values, no `node:*`/network/child-process/timer/random APIs, `new Date(`/`Date.now`/`Math.random`
absent — time and identity arrive only by injection. R4 satisfied (arch gate green with zero
violations; no allowance added).
