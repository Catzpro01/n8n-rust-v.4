### 1. What shipped

**`src/auth/security/authorization.mjs`** — default-deny authorization engine. `authorize()` runs 10 ordered checks over principal + tenant + action + resourceType + resourceId + capability + approval + step-up. No path to `allowed: true` falls through; every check denies by default. `createDecisionCache()` is bounded and version-aware, and **drops** (never serves) any entry whose SecurityStamp is not `STAMP_AUTHORITY.CURRENT`.

**`src/auth/security/permission-registry.mjs`** — derives the permission universe from the canonical n8n role source (`data/roles.json` via `compat/scopes.mjs`), never from a hand-written list: **122 permissions** (121 global + 47 project + 5 credential + 9 workflow, deduped), compiled to dense numeric ids, memoised in a `WeakMap`. This is what satisfies the #216 critical invariant — an unknown scope fails closed because it is not in the canonical universe.

**`security-error.mjs`** — `UNKNOWN_PERMISSION: 'auth.forbidden'`: the same published code as `PERMISSION_DENIED` (no new error vocabulary), reported distinctly via `details.unknownPermission`.

### 2. Defect 1 — P5.1's scope shape rejected 53% of the real vocabulary

*This is a cross-slice bug in my own P5.1 code, found by P5.3.*

`principal.mjs compilePermissions` enforced `/^[a-z][a-z0-9-]*:[a-z][a-z0-9-]*$/` (lowercase only). The canonical n8n vocabulary is camelCase **in both halves**. Measured: **65 of 122 permissions rejected**, including `aiAssistant:manage`, `annotationTag:create`, `chatHubAgent:read`, `communityPackage:install`, `credential:shareGlobally`. A principal compiled from a real global role could not be constructed at all. P5.3, which loads the actual universe, is what exposed it.

**Fix:** widened to `/^[a-z][a-zA-Z0-9-]*:[a-z][a-zA-Z0-9-]*$/`. Still a strict allowlist — rejects spaces, a missing colon, an uppercase first letter, a leading digit, punctuation, surrounding whitespace; the length bound is unchanged. Verified: accepts 122/122 canonical permissions, rejects `DROP TABLE`, `''`, `workflow`, `workflow:`, `:read`, `workflow:READ`, `work flow:read`, `workflow:read;drop`, `<script>:x`. The unknown-permission check against the registry remains the real gate; this only rejects malformed input earlier.

**Regression tests, both sides:** P5.1 asserts camelCase is accepted *and* malformed input still is not; P5.3 asserts all **122 permissions round-trip** through `PrincipalSnapshot` and `authorize()` — the strongest form of the guard.

### 3. Defect 2 — the cache was slower than not caching

The first measured run: `authorize()` **948 ns** vs `authorizeCached()` **4,463 ns**. The cache was a **4.7x pessimization**. Four causes, all fixed:

| Cause | Measured cost | Fix |
|---|---|---|
| `cacheKeyFor` hashed the key with SHA-256 | ~2,000 ns | Plain string join. The key never leaves the process and is never compared against attacker input, so no digest is warranted. |
| `evaluateStampAuthority` allocated `stale`/`ahead` arrays per call | ~4,000 ns | Added `isStampCurrent`, an allocation-free twin, for the read path. |
| `isStampCurrent` called `isSecurityStamp` twice; that helper reads `value[field]` through a loop variable — a dynamic keyed load measured at **260 ns vs 5 ns** for identical checks with direct property access | 535 ns | Unrolled it → **4.7 ns**. |
| Hit path rebuilt the decision with `{ ...decision, cached: true }` and re-inserted into the Map on every read | ~1,200 ns | Frozen shared object built once at insert; LRU touch skipped when the entry is already newest. |

Because `isStampCurrent` is now hand-unrolled for speed, **a test pins it to `evaluateStampAuthority(...).verdict === CURRENT`** over a matrix of valid, stale, ahead and garbage stamps, on both the presented and the authority side. The readability cost is only acceptable with that pin in place — and the pin exists.

### 4. Measured benchmark (node v20.20.2, linux/x64, 200k iters, fresh clone of merged main)

| Operation | First run | After | Ops/sec |
|---|---:|---:|---:|
| `authorize` (ALLOW, uncached) | 948 ns | **841 ns** | 1,189,442 |
| `authorize` (DENY, missing scope) | 758 ns | **754 ns** | 1,325,585 |

| `stamp validation alone` | 4,069 ns | **499 ns** | 2,002,245 |
| heap per cached op | 65.2 B | **9.5 B** | — |

The cache now earns its place: **1.64x faster than uncached** (841 → 511 ns) at **9.3x less allocation** (88.3 → 9.5 B/op).

Latency distribution — `authorize` ALLOW: p50 **601** / p95 **901** / p99 **2,227** ns. `authorizeCached`: p50 **505** / p95 **786** / p99 **1,102** ns.

Bounded cache under churn: 200,000 distinct keys against a 4,096-entry cap → final size **4,096** (cap held), heap delta **1,088 KiB**. No unbounded growth.

Concurrency: 200 principals interleaved, **787 ns** per call.
