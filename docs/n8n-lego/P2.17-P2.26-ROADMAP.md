## P2.17 — Agent Machine Runtime Foundation

- **Purpose / problem:** P2.16 defines model + graph semantics but executes nothing; P2.17 builds
  the bounded runtime foundation that *executes* those semantics deterministically.
- **Inputs:** verified `ai.agent-machine@1.1.0` on `main`; frozen P2.16 semantics; contract-lock
  conventions. **Outputs:** runtime foundation consuming (never redefining) the 1.1.0 contract.
- **Depends on:** P2.16 1.1.0 merged & Manager-verified. **Public contracts:** consumes
  `ai.agent-machine@1.1.0`; no new public contract without scope review.
- **Semantics:** lifecycle create/prepare/start/step/pause/resume/cancel with explicit state
  (no undefined states); bounded sequential/parallel/branch/fan-out/fan-in/join/retry execution;
  maximum concurrency, maximum children, bounded retry, deadline propagation, cancellable
  (runtime→task→child, idempotent repeated cancel), backpressure (accepted/queued/running/rejected/
  cancelled/completed/failed), deterministic transitions, request/operation identity for
  idempotency; session-scoped correlation-aware causation-aware sanitized runtime events;
  fail-closed on invalid capability/operation/state/graph/permission, budget exhaustion and
  deadline expiry.
- **Testable acceptance:** contract untouched (runtime consumes, never redefines); lifecycle
  transitions valid/invalid as specified; every bound enforced (concurrency, children, retry
  ceiling, deadline, cancellation, backpressure, capability fail-closed); repeated lifecycle
  requests deterministic; events deterministic and free of secrets/hidden reasoning; regression
  tests cover each criterion.
- **Tests / gates:** focused runtime suites + full backend/frontend + arch/foundation/capability/
  scaleout/`.ai` gates + XA-21 measure/report (pin untouched); official validation on the Windows
  self-hosted runner.
- **Security / resource boundaries:** no model inference, no LLM provider, no MCP, no shell,
  no filesystem, no unrestricted network, no secrets, no external agent spawning, no production
  distributed scheduler.
- **Non-scope:** P2.18 transport kernel, P2.19 artifact/approval, P2.20 MCP boundary, P2.21
  adapter stack, P2.22+ later milestones, XA-21 pin changes.
- **Exit:** PR opened with evidence; merged under the canonical merge protocol (Agent 1 merges the valid PR; Manager retains milestone authority); runtime foundation verified on `main`.

## P2.18 — Universal Transport & Envelope Kernel

- **Purpose:** one bounded envelope + transport-neutral kernel so CALL/EVENT/STREAM/BATCH move
  through a single validated shape with backpressure.
- **Inputs/Outputs:** P2.17 runtime events + existing envelope/interaction contracts → published
  kernel contract(s), deterministic codecs, bounded queues (declared, not unbounded).
- **Depends on:** P2.17. **Public contracts:** extends `lego.envelope`/`lego.interaction`
  conventions; no internal HTTP/broker/daemon.
- **Semantics:** deterministic encode/decode, validation on entry, STREAM backpressure mandatory,
  bounded buffers, fail-closed malformed envelopes, correlation/causation passthrough.
- **Acceptance:** round-trip determinism, malformed-rejected, backpressure observed under load,
  no unbounded queue anywhere; tests + gates as in P2.17.
- **Non-scope:** MCP (P2.20), adapters (P2.21), model inference, distributed infra.
- **Exit:** kernel on `main` via the canonical merge protocol (Agent 1 merges the valid PR).

## P2.19 — Artifact, Approval & Audit Foundation

- **Purpose:** bounded artifact references, fail-closed approval boundary and low-volume
  architectural audit records that P2.16 waiting/approval semantics already point at.
- **Depends on:** P2.17 (parallel with P2.18). **Public contracts:** artifact + approval contract
  publication (currently contract-only capabilities).
- **Semantics:** reference-only artifacts (no filesystem authority), approval request/grant/deny
  lifecycle owned here (Agent Machine only carries references), audit events architecturally
  scoped, deterministic ids, bounded metadata.
- **Acceptance:** waiting machines can be resolved by the approval contract without P2.16
  changes; artifact refs stay opaque; audit volume bounded; no secrets in artifacts; full gates.
- **Non-scope:** MCP, adapters, transport kernel internals.
- **Exit:** canonical merge protocol (Agent 1 merges the valid PR); P2.16 waiting boundary now resolvable by dependency, not by edit.

## P2.20 — MCP vs Agent Control Boundary

- **Purpose:** declare where MCP (interoperability) ends and agent control authority begins —
  state machine for permission-required/exposed/blocked, never implicit authority.
- **Depends on:** P2.18 + P2.19. **Public contracts:** MCP boundary declaration (FUTURE server
  implementations stay P3/FUTURE).
- **Semantics:** four declared MCP states, no transport claim, explicit permission gates,
  fail-closed on unknown server/capability; control plane never delegates to MCP implicitly.
- **Acceptance:** boundary tests prove refusal of undeclared servers, authority never inferred,
  vocabulary quoted with provenance; no network in tests.
- **Non-scope:** actual MCP server/client implementation (P3/FUTURE), GitHub provider (P2.26).
- **Exit:** canonical merge protocol (Agent 1 merges the valid PR; post-merge verification on `main`).

## P2.21 — Runtime Adapter & Harness Stack

- **Purpose:** adapter seam letting an external runtime satisfy P2.16/P2.17 contracts plus a
  bounded test harness (in-process/simulated only).
- **Depends on:** P2.18 + P2.19. **Public contracts:** runtime adapter contract (EXTERNAL
  executorKind becomes real behind the seam).
- **Semantics:** EXTERNAL kind requires explicit provider support (already fail-closed in 1.1.0),
  harness runs bounded scenarios deterministically, no shell/filesystem authority granted by
  adapter selection.
- **Acceptance:** same contract, different locality — P2.16 contract tests re-run against the
  adapter unchanged; harness covers cancel/deadline/backpressure; full gates.
- **Non-scope:** node portability (P2.22), model inference, production scheduler.
- **Exit:** canonical merge protocol (Agent 1 merges the valid PR; post-merge verification on `main`).

## P2.22 — Node Compatibility & Portability

- **Purpose:** portability rules so nodes (and later agent-built nodes) run equivalently across
  JS/Rust/WASM targets without changing the contract.
- **Depends on:** P2.21. **Public contracts:** node contract profile extension (data, not codegen).
- **Semantics:** language-neutral schema subset honored, capability declaration required,
  portability matrix testable, no build step becomes source of truth.
- **Acceptance:** round-trip fixtures validate on every target declared portable; unportable
  constructs declared, not silently dropped.
- **Non-scope:** Node Creator itself (P2.23), provider integrations (P2.26).
- **Exit:** canonical merge protocol (Agent 1 merges the valid PR; post-merge verification on `main`).

## P2.23 — Node Creator & Translation Foundation

- **Purpose:** bounded creator + translation foundation (JS↔declared schema) with approval touch
  points; human-creates/node-creates share one validation path.
- **Depends on:** P2.22 + P2.19. **Public contracts:** node-creation contract + translation
  profile.
- **Semantics:** deterministic translation, validation identical to import path, artifacts of
  creation are references, creator has zero standing authority (capability + approval required).
- **Acceptance:** generated nodes pass the same gates as hand-written ones; refusal cases
  deterministic; no execution authority leaks into creator.
- **Non-scope:** autonomous self-modification, production publishing pipeline (P3/FUTURE).
- **Exit:** canonical merge protocol (Agent 1 merges the valid PR; post-merge verification on `main`).

## P2.24 — Token & Usage - honest accounting

- **Purpose / problem:** account for token & cost usage honestly — every figure carries
  `reported` / `estimated` / `unavailable` provenance; a number the source did not report is
  never fabricated as fact, never silently turned into `0`, and never presented as exact.
  Canonical `milestones.json` row: *Token & Usage - honest accounting* (phase D, XA-17).
- **Depends on:** P2.23 + P2.13 (token vocabulary `message`/`modelInput`/`output`), decided by
  **XA-17**. **Public contracts:** exactly one canonical usage contract under `ai-foundation` —
  `ai.token-usage@1.0.0` (operations `record | query | budget`; permissions
  `ai:usage:read | ai:usage:write`). No second publisher, no parallel vocabulary.
- **Semantics:** record value + kind + source + certainty; `reported` only when the source
  actually supplied the figure; `estimated` only via a deterministic, identifiable, versioned
  estimator (never labelled reported); `unavailable` when neither exists (never `0`). Cost only
  from reported usage + known pricing basis + a declared calculation rule — missing pricing ⇒
  `unavailable`; no guessing, no fetched prices, no billing settlement. Identity-keyed
  idempotency (retries never double-count). Injected `now`/`newId`; zero-builtin module; no
  prompt/completion/reasoning/credential capture — counts only, never content.
- **Acceptance:** reported/estimated/unavailable stay distinct under test; unknown never becomes
  zero; cost never fabricated; duplicate/retry deterministic; secrets never appear in records;
  contract/registry/capability three-way parity; P2.13 vocabulary byte-identical; boot payload
  unchanged (18,126 B pin); full gates.
- **Tests / gates:** focused usage suite + full backend/frontend + arch/foundation/capability/
  scaleout/`.ai` gates + XA-21 measure/report (pin untouched); official validation on the Windows
  self-hosted runner when available (PENDING reported truthfully otherwise).
- **Non-scope:** token provider SaaS integration, external metering API, billing/invoicing/
  payment, model inference, LLM runtime, production scheduler, shell/filesystem/subprocess
  authority, MCP runtime, credential manager, Arena runtime, prompt/completion telemetry,
  semantics changes to P2.13 Context & Session or P2.23 Node Creator/Translation.
- **Exit:** implementation PR merged by Agent 1 when valid; completion transition merged;
  post-merge verification green on `main`; register advanced (canonical merge protocol:
  `agentCompletionIsMergeExecution: true`).

## P2.25 — Universal Agent Bridge

- **Purpose:** bridge multiple agent identities/runtimes behind one bounded control surface —
  built strictly from P2.21 adapter + P2.20 boundary + P2.24 honest usage accounting.
- **Depends on:** P2.21 + P2.20 + P2.24. **Public contracts:** bridge contract (orchestration
  metadata, never authority).
- **Semantics:** bridge is bookkeeping like delegation: narrowed grants, no inheritance,
  fail-closed unknown peers, bounded fan-in/out of control messages through P2.18 envelopes.
- **Acceptance:** cross-runtime scenario tests all run through existing contracts; no new
  authority word appears; refusal paths deterministic.
- **Non-scope:** provider integrations (P2.26), production distributed scheduler (FUTURE).
- **Exit:** implementation PR merged by Agent 1 when valid; completion transition merged;
  post-merge verification green on `main` (canonical merge protocol).

## P2.26 — Provider, Workspace & GitHub Integration + Foundation Readiness

- **Purpose:** converge the program: declared providers (sim/local/cloud — not secrets),
  workspace/GitHub integration boundaries (no standing credential), and a Foundation-readiness
  re-verification of every P2.16–P2.25 invariant.
- **Depends on:** P2.20 + P2.22 + P2.23 + P2.25 (see diagram). **Public contracts:** provider
  declaration profile; GitHub integration stays a declared capability boundary.
- **Semantics:** providers declared not assumed, credentials never stored by LEGO, GitHub access
  only via explicitly handed-over authorization, readiness gate re-runs the full ladder
  (arch/foundation/capabilities/scaleout/`.ai`/full suites/XA-21 measure-report).
- **Acceptance:** readiness checklist all green on `main`; every milestone exit evidenced;
  no pin, test or governance file weakened to achieve green.
- **Non-scope:** P3/FUTURE items (real MCP server, distributed scheduler, autonomous publishing),
  anything after P2.26.
- **Exit:** implementation PRs merged by Agent 1 when valid; program-level reconciliation stays
  with the Manager (architecture and milestone authority).
