Final acceptance for the entire P9 observability lane: codify the **twelve-gate FINAL NON-INTERFERENCE GATE**, OFF-vs-NORMAL workflow equivalence, and the milestone status vocabulary. The acceptance suite wires the twelve gates to the live P9 modules and produces a deterministic roll-up (`finalAcceptance`).

## Readiness semantics

- **`laneReadyForMergeReview`** — twelve gates + equivalence pass and P9.1–P9.21 are COMPLETE in the lane inventory (PRs open, CI green). This is what Agent 4 can achieve.
- **`mergeReady`** — additionally every milestone including P9.22 is COMPLETE, which requires **merge + verified_main** — owned by the Manager per lane policy (delegate never merges to main).

## Known limitations (explicit)

1. P9.1–P9.21 are delivered as stacked open PRs (#176–#205); not yet on `main` — Manager integrates.
2. Profiling and eBPF adapters are intentionally **not selected** (optional per DoD); isolation proven via kill-switch/A-B, not live adapters.
3. Disk spill-to-disk has no real filesystem path in this lane (no I/O modules); byte-budget `budget_shed` is the in-repo proof of quota shedding.
4. Benchmarks are sandbox microbenchmarks (Node 22); production RSS/CPU must be re-measured post-merge on target hardware.
5. `operator query storm` proves bounded API behavior + workflow independence, not full multi-tenant load shaping (see P9.19).

## Rollback strategy (final)

1. **Lane rollback** — each slice is an independent stacked branch; drop a PR to remove that slice; parents remain valid.
2. **Contract rollback** — lock rows are append-only; deprecate via status/notes rather than delete; consumers pin versions (`compat` ranges).
3. **Runtime rollback** — every P9 advanced feature has a kill-switch (P9.21) and low-resource mode exits to NORMAL (P9.17); telemetry OFF is always a valid configuration (`disabled` construction + kill-switches).
4. **Data rollback** — retention tiers (P9.15) and replay evidence (P9.14) allow time-bounded restore of prior evidence without rewinding workflow state.
5. **Post-merge incident** — revert the merge commit on main (Manager), re-run §18 verification + post-merge smoke; branches remain for cherry-pick.
