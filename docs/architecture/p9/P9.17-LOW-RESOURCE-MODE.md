# P9.17 — Low-Resource Observability Mode

Slice: P9.17 · Contract: `observability.low-resource-mode@1.0.0` · Owner: agent-6 (product) / Agent 4 (implementation, Issue #101)

## Problem

On small VPS boxes, telemetry must **degrade before the workflow does**. P9 needs an explicit low-resource mode: automatic or manual activation, a defined shed order that never touches audit/security, hard P9 budgets, hysteresis + cooldown so the mode does not thrash, and a tested recovery path — while workflow A/B results stay identical.

## Contract

| Export | Role |
|---|---|
| `LOWRES_MODES` | `NORMAL` ↔ `LOW_RESOURCE` |
| `LOWRES_DEGRADE_ORDER` | `debug → verbose → sampled_metrics → traces → logs → diagnostics → audit_security` |
| `LOWRES_STEP_EFFECTS` | Observable effect per step; `audit_security: never-shed` |
| `createLowResourceController` | Budgets + hysteresis + cooldown + initial mode |
| `observe` | Auto (pressure ≥ enter / ≤ exit) or explicit mode change; cooldown blocks thrash |
| `degradeOneStep` | Advance one step in defined order |
| `admit` | Admit / shed / protected / budget_shed under mode + budgets |
| `workflowAb` | Pure business transform — result independent of telemetry mode |
| `snapshot` | Deterministic counters, channelsOff, usage, pressure |

### Semantics

- **Activation** — automatic via `memoryUsedBytes`/`cpuUsedPct` vs enter/exit thresholds, or `explicit` mode in the sample.
- **Hysteresis** — `exitThresholdPct < enterThresholdPct` required at construction.
- **Cooldown** — transitions within `cooldownMs` increment `thrashBlocked` and do not flip.
- **Budgets** — whole-record `budget_shed` when over `byteBudget` or over `cpuBudgetPct`; never partial mutation.
- **Critical/security** — `audit_security` always `protected`, even past budget (degraded floor, honest counter).
- **Recovery** — cooldown-elapsed low pressure (or explicit) restores `NORMAL`, clears `channelsOff`.
- **Workflow A/B** — `workflowAb` only applies `transform(input)`; mode is metadata, not an input to the result.

## DoD mapping

| DoD requirement | Evidence |
|---|---|
| Auto or explicit activation | pressure sample + `explicit` mode tests |
| Defined degrade order | step walk equals `LOWRES_DEGRADE_ORDER` |
| Budgets enforced | byte + cpu `budget_shed` counters |
| Workflow correctness stable | A/B deepEqual across NORMAL vs LOW_RESOURCE |
| Memory/CPU reduction measurable | admission caps + snapshot usage/counters |
| Hysteresis/cooldown | thrashBlocked on flip-flop samples |
| Critical/security protected | `protected` outcome at floor + past budget |
| Recovery tested | mode NORMAL + `channelsOff` empty + admits resume |

## Required evidence fixtures

1. Memory pressure benchmark — `memoryPressure` + flood admits
2. CPU pressure benchmark — `cpuPressure` + `budgetCpuEnforced`
3. Mode transition test — `hysteresis.samples`
4. Recovery test — cooldown-elapsed exit
5. Workflow A/B correctness test — `workflowAb.inputs` across modes
