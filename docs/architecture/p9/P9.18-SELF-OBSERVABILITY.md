# P9.18 — Telemetry Self-Observability

Slice: P9.18 · Contract: `observability.self-observability@1.0.0` · Owner: agent-6 (product) / Agent 4 (implementation, Issue #101)

## Problem

P9 emits large volumes of telemetry, but the pipeline itself must be observable: how much was generated, dropped, sampled, buffered; when export fails; when redaction or cardinality limits fire; when queries are slow; when diagnostic bundle assembly fails; when the system is degraded. Without self-observability, an outage of the telemetry path is invisible — and "no errors" is indistinguishable from "no telemetry".

## Contract

| Export | Role |
|---|---|
| `SELFVIEW_COUNTERS` | Exactly the ten DoD counters — fixed key set |
| `SELFVIEW_ERROR_COUNTERS` | Subset that constitutes errors for health classification |
| `SELFVIEW_EVENT_KINDS` | `note(kind)` accepts only counter names (identity map) |
| `SELFVIEW_PRIORITIES` | P0–P4 for self-telemetry detail events |
| `SELFVIEW_SUPPRESSION` | Own rule: counters always update; P2–P4 detail delivery suppressed under outage; P0/P1 always delivered |
| `SELFVIEW_LIMITS` | Saturating max value, `maxDepth` re-entrancy guard, capacity bounds |
| `createSelfObservability` | `{ capacity, degradeAfterFailures, onNote }` — fail-closed null |
| `note` | Record one event; recursion-guarded; priority-filtered delivery |
| `offer` / `take` | Bounded buffered occupancy → `buffered` / `dropped` counters |
| `attemptExport` | Exporter result: failure marks outage, may bump `degraded` |
| `snapshot` | Counters + `zeroTelemetry`/`zeroErrors` (independent) + occupancy + outage |

### Semantics

- **Required counters** — `generated`, `dropped`, `sampled`, `buffered`, `export_failed`, `redacted`, `cardinality_rejected`, `query_slow`, `diagnostic_bundle_failed`, `degraded`.
- **Zero errors ≠ zero telemetry** — `snapshot().zeroTelemetry` and `zeroErrors` are independent booleans with a four-way `classification`.
- **Bounded self-metrics** — fixed keys (never grows), saturating safe integers, no dynamic labels; unknown kinds rejected.
- **No infinite recursion** — `maxDepth = 1`: a `note()` issued from inside `onNote` returns `selfview.recursion` and bumps `internal.recursion_suppressed` only.
- **Own suppression/priority rule** — under outage, P2–P4 detail delivery is suppressed (`internal.detail_suppressed`) while counters still bump; P0/P1 always delivered; recovery re-enables detail.
- **Outage → degraded** — `degradeAfterFailures` consecutive export failures bump `degraded` once; success clears outage/degraded flags while cumulative counters stay honest.
- **No I/O, no clock, no workflow/execution import** — sole import `./telemetry-redaction.mjs`.

## DoD mapping

| DoD requirement | Evidence |
|---|---|
| Report the ten counters | `note()` over `pipelineSequence` + snapshot keys |
| Distinguish zero errors from zero telemetry | independent booleans + four-way classification |
| Self-metrics bounded | fixed key set; unknown kind rejected; saturating limit |
| No infinite recursion | `onNote` re-entry → `selfview.recursion`, single bump |
| Own suppression/priority rule | outage P3 suppressed / P1 delivered; counters unaffected |
| Simulated telemetry outage | repeated `attemptExport(false)` + self-notes still count |
| Drop-counter test | capacity offers → `dropped` exact |
| Exporter failure | `export_failed` + `degraded` after threshold |
| Recursion guard | dedicated re-entrancy test |

## Required evidence fixtures

1. Simulated telemetry outage — `outage.failures` × `attemptExport(false)`
2. Drop-counter test — `drop.capacity` / `drop.offers`
3. Exporter failure — `export_failed` + `degradeAfter` → `degraded`
4. Recursion guard — `onNote` re-entry suppressed
