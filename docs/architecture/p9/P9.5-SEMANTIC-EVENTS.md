# P9.5 — semantic event contract and lifecycle events

Authority #101 P9.5; product owner Agent 6, implementation delegate Agent 4.
Preflight: baseline main `24032a0c` (P6.13 merge); P9.1–P9.4 verified merged.
No P3/P4/P6/P8 import, no scheduling, no admission decision, no runtime hook.

## Contract and vocabulary

`observability.semantic-event@1.0.0`, native module
`apps/n8n-lego/src/lego/semantic-events.mjs`. Structural schema:
[semantic-event.schema.json](semantic-event.schema.json). Fixtures:
`apps/n8n-lego/test/fixtures/p9/semantic-events.json`.

Published vocabulary (20 names, schemaVersion `1.0.0` each):

| Domain | Events (lifecycle boundary) |
| --- | --- |
| execution (P3) | execution.started, execution.completed, execution.failed, execution.cancelled |
| checkpoint (P3) | checkpoint.created, checkpoint.resumed |
| trigger (P4) | trigger.received, trigger.failed |
| ingress (P4) | ingress.admitted, ingress.rejected, ingress.deferred, ingress.duplicate, ingress.rate_limited |
| node (P6) | node.loaded, node.quarantined, node.released |
| registry (P6) | registry.epoch_published, registry.epoch_rolled_back |
| runtime (P6) | runtime.lease_acquired, runtime.lease_released |

Names quote boundary OUTCOMES only. P9 does not decide admission, scheduling,
node resolution or lease state; producers in those domains (or contract-level
fakes) emit these names without P9 waiting on their implementations. Unknown
event names and unsupported schema versions never admit
(`classifyEventVersion` → `unknown_event` / `unsupported_version`).

## APIs

1. `createSemanticEvent(spec, context)` — requires a branded P9.1 context,
   published `eventName`, envelope `timestamp` + `component`. Optional
   `schemaVersion` must equal the published version; optional `sequence` is a
   nonnegative safe integer. Attributes use the P9.2 numeric/boolean allowlist;
   unknown attribute names increment `redactionCount` and their values are
   never read. No message text, payload, stack, header bag or artifact bytes —
   `artifactRef`/`diagnosticRef` stay opaque envelope identifiers. Invalid
   input returns `null` (telemetry rejection, never workflow failure).
2. `serializeSemanticEvent` / `deserializeSemanticEvent(wire, policy?)` —
   deterministic field order, exact contract version `1.0.0`, bounded ASCII
   JSON ≤ `EVENT_LIMITS.wireBytes` (12288). Unknown contract versions, unknown
   names, unsupported schema versions and non-canonical encodings all return
   `null` (no migration, no partial admission). Tenant capture on decode needs
   the same explicit P9.1 `policy.authorizedTenantId` as encode.
3. `createEventOrderGate({maxKeys, policy?})` — explicit duplicate/out-of-order
   policy per key. `monotonic` (default): equal sequence → `duplicate`, lower →
   `out_of_order`, higher (including gaps) → `accepted`. `unordered`: any
   nonnegative sequence admits. `maxKeys` is required (1..65536); a new key
   beyond the budget answers `capacity`; invalid key/sequence answers
   `rejected`. Stats are bounded counters only — no event retention.

## Lifecycle coverage

Fixture lifecycles walk every published name:

- happy path: trigger → ingress.admitted → execution.started → node.loaded →
  runtime.lease_acquired → checkpoint.created/resumed → execution.completed →
  lease released → node released, shared correlation `exec-1` on every event;
- failure path: trigger.failed, ingress rejected/deferred/duplicate/
  rate_limited, execution failed/cancelled, node.quarantined, registry
  epoch published → rolled_back.

Order sequences on the happy path admit through the monotonic gate
1..10; the fixture's `orderPolicy` table pins duplicate/out-of-order answers.

## Security and bounds

- Vocabulary is a closed enum on the wire; producers cannot invent names.
- Attribute bag: ≤ 8 keys, allowlisted numeric/boolean only; wrong-typed known
  keys reject the whole event (fail closed); unknown keys redact without read.
- Wire ≤ 12288 ASCII bytes; max-occupancy fixture proves the ceiling holds.
- No secret-shaped free text slot exists; identifier rules reuse the P9.1
  envelope (URLs, token shapes and control characters rejected).
- Creation path performs no JSON encoding, clock read, network, disk or
  callback (asserted by test with `JSON.stringify`/`Date.now` traps).

## Non-goals (explicit)

No buffer/export (P9.6), no general classification engine (P9.7), no sampling
(P9.8), no causal graph (P9.13), no operator API (P9.16). Events are admitted
values only; persistence and retention are later slices.
