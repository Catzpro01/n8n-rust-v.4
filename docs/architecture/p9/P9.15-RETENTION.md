# P9.15 — Retention + Hot/Warm/Cold Policy

Slice: P9.15 · Contract: `observability.telemetry-retention@1.0.0` · Owner: agent-6 (product) / Agent 4 (implementation, Issue #101)

## Problem

Telemetry without retention policy grows until it competes with workflow memory.
P9 owns the retention plane: **HOT → WARM → COLD** residence, signal-specific
TTLs, deterministic expiry, incident-driven extension under policy, and safe
degradation when storage pressure hits — without ever touching authoritative
workflow state.

## Contract

| Export | Role |
|---|---|
| `RETENTION_TIERS` | `HOT` / `WARM` / `COLD` residence classes |
| `RETENTION_SIGNALS` | `log`, `metric`, `trace`, `audit`, `security`, `replay`, `diagnostic` |
| `createRetentionPolicy` | Signal-specific `{hotMs, warmMs, ttlMs, incidentExtendMs, maxIncidentExtendMs}` + incident gate; defaults differ per signal |
| `classifyResidency` | Pure `(ageMs, policy) → HOT\|WARM\|COLD\|EXPIRED` |
| `createRetentionStore` | Bounded telemetry-only store (no workflow/execution/credential maps) |
| `ingestRecord` | Admit telemetry; refuse authoritative kinds + secret shapes |
| `applyRetentionPass` | Deterministic transitions + **actual removal** of expired records |
| `extendForIncident` | Policy-controlled, allow-listed, capped extension |
| `applyStoragePressure` | Shed P4→P1 first; **P0 audit/security last**; never mutate payloads |
| `deleteTelemetryRecord` | Delete telemetry ids only; `refused_authoritative` for state probes |
| `retentionReport` | Deterministic sorted histogram + stats |

### Semantics

- **Signal-specific TTL** — one global TTL is a bug; defaults table in-module.
- **Deterministic expiry** — `(record, policy, now)` → same removal every time; no clock inside the module.
- **Incident extension is policy-controlled** — `allowExtension`, signal allow-list, `min(extendMs, incidentExtendMs, maxIncidentExtendMs)`.
- **Audit/security ≠ normal telemetry** — longer default TTLs; shed last under pressure.
- **Deletion isolation** — store never holds `workflow` / `execution` / `checkpoint` / `credential` / `triggerRegistration` / `nodeRegistry`.
- **Pressure degrades before corruption** — whole-record shed only; budgets enforced; P0 may leave the store "degraded over floor" rather than corrupting bytes.
