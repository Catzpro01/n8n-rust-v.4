| Mode | elapsed ms | ops/s | batch-mean p50 / p95 / p99 (microseconds) |
| --- | ---: | ---: | --- |
| arithmetic OFF control | 1.796 | 55,674,358 | 0.014 / 0.020 / 0.049 |
| native record, shared context | 232.627 | 429,873 | 2.068 / 3.258 / 3.349 |
| cold context + record | 386.352 | 258,831 | 3.258 / 5.678 / 6.742 |
| record + slow-path codec | 313.832 | 318,642 | 2.824 / 3.677 / 12.049 |

Shared-context mode: CPU user 236,907 us / system 34 us, pre-GC heap delta
504,272 bytes, retained heap delta after GC 12,784 bytes, measured RSS delta 0.
These are process/GC observations, **not allocation counts, per-event latency
percentiles, isolated CPU overhead, or workflow performance**. Native JS record
creation is not allocation-free. No queue is retained. Each batch has 1,000
operations; JIT, GC and shared sandbox noise apply. Full T0–T14 and end-to-end
non-interference remain P9.22, not asserted by this slice.

## Limitations / delivery

structured-log implementation is delivered. Arbitrary secret bytes disguised as
opaque IDs cannot be detected universally; producers must supply trusted
non-secret references. Hostile in-process code requires its owning sandbox.

record records verified merged main. Do not interpret this evidence as COMPLETE.
