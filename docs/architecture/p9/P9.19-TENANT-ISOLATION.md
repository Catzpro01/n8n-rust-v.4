# P9.19 — Multi-Tenant Telemetry Isolation Readiness

Slice: P9.19 · Contract: `observability.tenant-isolation@1.0.0` · Owner: agent-6 (product) / Agent 4 (implementation, Issue #101)

## Problem

Shared telemetry pipelines must be ready for multi-tenant deployments without leaking one tenant's signals into another's queries or exports — while single-tenant installs (the common case) pay zero multi-tenant overhead. Global operational aggregates need a separate, explicitly granted path so "the platform is healthy" never conflates with "tenant A is healthy".

## Contract

| Export | Role |
|---|---|
| `TENANTISO_MODES` | `single` (lightweight flat bucket) / `multi` (tenant-scoped Map) |
| `TENANTISO_SCOPES` | `tenant` vs `global` — never interchangeable |
| `TENANTISO_LABEL_DENY` | Tenant-identifying metric label keys (deny on sight + `/tenant/i`) |
| `TENANTISO_LIMITS` | Identifier/channel/record/tenant/label bounds |
| `createTenantIsolation` | `{ mode, maxRecords, maxTenants, globalAggregates }` — fail-closed null |
| `ingest` | multi requires `tenantId`; single forbids it |
| `query(auth, filter)` | Auth-scoped rows; cross filter → `tenantisolation.cross_scope` |
| `routeExport(auth, job)` | Record tenant must equal auth tenant; else fail closed |
| `tenantAggregate(auth)` | `scope:'tenant'` counts for one tenant |
| `globalAggregate(auth)` | `scope:'global'` counts only — requires `scope:'global'` auth **and** deployment grant; `containsTenantRows:false` |
| `sanitizeMetricLabels` | Tenant-identifying keys → `tenantisolation.tenant_label` |
| `snapshot` | mode, tenants, counters, `lightweight` structural proof |

### Semantics

- **Tenant scope where authorized** — multi queries/routes require `{ tenantId }`; global requires `{ scope:'global' }` + `globalAggregates:true`.
- **Queries enforce scope** — filter tenant ≠ auth tenant → `cross_scope` + `cross_tenant_blocked` counter; no rows returned.
- **Export routing respects scope** — job tenant must equal auth tenant (multi) or be absent (single).
- **Cross-tenant leakage fails closed** — every path returns a typed error, never partial data.
- **Global aggregates separated** — counts-only report tagged `scope:'global'`; raw cross-tenant row dumps refused even with global auth.
- **Tenant ids ≠ metric labels** — fixed denylist + `/tenant/i` pattern; rejections counted.
- **Single-tenant lightweight** — one array, no `Map`, no auth required, `snapshot().lightweight.tenantMapAllocated === false`.
- **No I/O, no clock, no workflow/execution import** — sole import `./telemetry-redaction.mjs`.

## DoD mapping

| DoD requirement | Evidence |
|---|---|
| Tenant scope in contract where authorized | multi auth validation + scopes export |
| Queries enforce tenant scope | A/B isolation + cross_scope tests |
| Export routing respects scope | own route OK / cross route fail |
| Cross-tenant leakage fails closed | unauthorized query + route + aggregate |
| Global aggregates separated | `scope:'global'`, `containsTenantRows:false` |
| Tenant ids not automatic metric labels | denylist walk + `/tenant/i` |
| Single-tenant lightweight | flat bucket, no Map, no auth |
