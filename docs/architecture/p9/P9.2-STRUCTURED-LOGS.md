# P9.2 — structured logs and versioned error taxonomy

Authority: #101 P9.2 DoD. Product owner Agent 6, implementation delegate Agent 4.
Preflight baseline: `1a7fc1aa` (P9.1 merged and post-merge gate passed).
Only P9.2 is implemented here; P9.1's envelope version remains 1.0.0.

## Contract

`observability.structured-log@1.0.0` publishes:
- `STRUCTURED_LOG_CONTRACT`, `LOG_LIMITS`, `LOG_ERROR_CLASSES`, `LOG_ERROR_TAXONOMY`;
- `classifyLogError(code)`, `createStructuredLog(spec, context)`,
  `serializeStructuredLog(log)`.

Schema: [structured-log.schema.json](structured-log.schema.json).
Examples/taxonomy fixtures: `apps/n8n-lego/test/fixtures/p9/structured-log.json`
and `error-taxonomy.json`.

A log is `{ contractVersion, envelope, attributes, redactionCount }`.
Its native P9.1 envelope carries signalType=LOG, timestamp, severity, component,
operation, outcome, optional environment/errorCode/errorClass/artifactRef/
diagnosticRef and the immutable reusable correlation context. Timestamp,
severity, component, operation and outcome are mandatory; free text cannot
substitute for them. `TRACE DEBUG INFO WARN ERROR FATAL` is reused from P9.1,
not independently defined. Invalid input returns null, never a workflow failure.
The source has no stream/sink/console write. Caller lifetime/GC owns admitted logs.

## Error taxonomy 1.0.0

The existing `lego.error-contract@1.2.0` remains authoritative for codes and
retryability. Its public module is read once at import, not on every log.
No new source error code, message, status or retry policy is invented or changed.

Diagnostic classes: AUTHENTICATION, AUTHORIZATION, VALIDATION, NOT_FOUND,
CONFLICT, CAPACITY, CANCELLATION, TIMEOUT, UNAVAILABLE, INTERNAL, UNSUPPORTED.
Mapping is deterministic from source HTTP status (401/403/400/404/409/413+429/
499/504/503/500/501 respectively), with explicit code-semantic exceptions:
`execution.timeout` => TIMEOUT; `node.catalog_unavailable` and
`storage.unavailable` => UNAVAILABLE. This is a diagnostic projection, not a
business outcome or HTTP policy. Missing source retryability stays null.

Unknown/malformed code returns null. Caller-supplied errorClass or Error object
is rejected. Classification never inspects text, stack or nested cause. The
versioned fixture pins all current source codes/classes/retryability; catalog
changes must update the taxonomy deliberately and pass conformance tests.

## Bounds and redaction BEFORE retention/serialization

- At most 8 input attributes, at most 64 characters per attribute name.
- Output allowlist: durationMs, attempt, itemCount, byteCount (nonnegative safe
  integers), statusCode (100..599 integer), cacheHit (boolean).
- No string, nested object, array, binary data or payload attribute survives.
- Unknown attribute names/values are discarded without reading values. Each
  increments redactionCount; even a getter for a secret value is never invoked.
- Optional input message is capped at 2048 characters and **always omitted**,
  even when it looks harmless. Only its presence increments redactionCount.
  No regex-based promise that an arbitrary message is safe is made.
- Unknown top-level fields, raw exceptions, stack, credentials, headers and
  bodies reject the log. P9.1's non-secret identifier checks remain in force.
- At most 9 redacted fields are reported (8 input attributes + one message).
- Canonical serialization is capped at 12288 ASCII bytes. Only branded, admitted
  logs can serialize. Envelope bound is 8192 bytes; bounded numeric attributes
  and fixed metadata fit inside the additional budget. No codec I/O.

This is intentionally a narrow deny-by-default P9.2 policy, not the general
P9.7 classification/redaction engine. Trusted producers must still never encode
arbitrary credentials into identifier or numeric fields. Local input must be
bounded plain metadata; this API is not an isolation sandbox for hostile JS.

## Lifecycle, resource and degradation profile

Creation does bounded metadata validation, code lookup, small immutable objects,
and context sharing. No hot-path clock, encoding, payload clone, remote call,
stack capture, timer, queue or disk write. The existing foundation error module
performs its one-time catalog filesystem read during module initialization;
applications should load this optional contract outside workflow execution.

No log persistence, exporter, kernel logger replacement or runtime hookup is
included. A rejected log returns null, leaving business outcome untouched. The
existing `src/logger.mjs` is owned by platform-kernel and is **not** patched;
this slice does not claim to sanitize all legacy application logging.

Only exact current structured representation is emitted. No generic JSON log
reader is implemented in P9.2. Future adapters must validate version and fields,
not silently reinterpret unknown versions. P9.1 codec is unchanged.

new dependency consumes the existing public foundation error contract; it adds
no reverse dependency or ownership transfer. Exact inventory assertions change
40 -> 41 solely for this one new contract; no tests/gates are weakened.
