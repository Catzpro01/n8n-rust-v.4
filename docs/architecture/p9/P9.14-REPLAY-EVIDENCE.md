# P9.14 — Replay / Compatibility Evidence Integration

Slice: P9.14 · Contract: `observability.replay-evidence@1.0.0` · Owner: agent-6 (product) / Agent 4 (implementation, Issue #101)

## Problem

P3 owns checkpoint snapshots (`execution.state-stream`) and P6 owns compatibility
replay (`node.semantics`). P9 must surface those references in diagnostics and
diagnostic bundles — **without becoming a second replay engine** and without
silently accepting stale or foreign reference formats.

## Contract

| Export | Role |
|---|---|
| `REPLAY_EVID_FORMATS` | Pins P3 `execution.state-stream@0.1.0` / `snapshotVersion=1` and P6 `node.semantics@0.1.0` / `schemaVersion=1` |
| `checkReplayRef` | Shape + contract-id + version-field check only (never executes owning engines) |
| `compileReplayEvidence` | `{ refs }` → frozen `{ evidence, incompatible, evidenceMissing }`; secret/shape fail closed to `null` |
| `selectReplayRefsForBundle` | Maps first compatible P3 → `refs.checkpoint`, P6 → `refs.replay` |
| `attachReplayEvidence` | Merges slots into a diagnostic/bundle `refs` map without dropping artifacts |
| `exportReplayEvidence` | Deterministic `stableStringify` body, secret-safe |

### Semantics

- **Missing refs** → `evidenceMissing: ['replayRefs']` (safe, not an error).
- **Incompatible version / contract** → listed under `incompatible`, **never** in `evidence`.
- **Secret-shaped refs** → compile returns `null` (fail closed).
- **References ≠ engines**: sole import is `telemetry-redaction`; format pins are
  local data matching the published owners; tests assert it never calls
  `stateStreamFromSnapshot` / `replayCompatibility` / `replayFingerprints`.

## DoD mapping

| DoD requirement | Evidence |
