# P9.9 — Resource / Pressure Telemetry

Status: COMPLETE (stacked on P9.8) · Contract `observability.resource-pressure@1.0.0` · Owner agent-6 · Development delegate Agent 4 · Issue #101

## Purpose

Observe CPU/memory/disk/network and applicable runtime resources **without becoming a resource scheduler**. P9 reports the condition; P3/P4/P6 (or future policy domains) decide what to do. Readings are bounded; pressure transitions emit a degradation hint so P9 can degrade before the workflow runtime destabilizes.

## Provenance ladder (never fabricate)

| Provenance | Meaning |
|---|---|
| `OBSERVED` | Measured by this process/collection path |
| `ESTIMATED` | Derived (ratios, interpolations, process-local estimates) |
| `REPORTED` | Provider/host actually reported it — only when the caller supplies it; monitor never invents REPORTED |

## Pressure states (deep design §11)

`NORMAL` → `PRESSURED` → `CONSTRAINED` → `CRITICAL`, plus `UNKNOWN` (collector failure / no usable readings).

| State | Degradation level |
|---|---|
| NORMAL | 0 |
| UNKNOWN | 0 (distinct state; not a false green — see stats.collectorFailures) |
| PRESSURED | 1 |
| CONSTRAINED | 2 |
| CRITICAL | 3 |

`degradationHook` (optional) receives frozen transitions `{ from, to, dimension, degradation }` so downstream P9 policy (e.g. P9.17 low-resource mode) can react. Hook exceptions never break the monitor.

## Policy-driven thresholds

Defaults live in `DEFAULT_PRESSURE_THRESHOLDS` (fractions for utilization dims; absolute counts for queue/execution/connection dims). Operators override via `config.thresholds` or `setThresholds(policy)` — invalid policies fail closed (`false`) and leave the active policy unchanged. Classification is always `warn ≤ high ≤ critical`.

## Bounded readings

- History is a **fixed ring** (`historySize` ≤ 1024, default 256) — flooding readings only overwrites; `historyOverflowDrops` counts the pressure on telemetry itself.
- Latest values are at most `RESOURCE_DIMENSIONS.length` slots.
- Resource sampling **never** creates an unbounded queue (DoD: readings do not trigger unbounded telemetry).

## Fail-safe collector

`config.collector` runs inside `collect()`/`evaluate()`; exceptions → `{ error: true, state: 'UNKNOWN' }`, `stats.collectorFailures++`, state transitions to UNKNOWN. A subsequent good reading clears the unknown path. Collector never throws to the caller.

## DoD trace

| Requirement | Where |
|---|---|
| CPU/memory/disk/network + runtime resources observed | `RESOURCE_DIMENSIONS` + resource fixtures |
| observed vs estimated vs reported distinguishable | provenance test + `latestSnapshot()` |
| pressure states NORMAL…UNKNOWN | `PRESSURE_STATES` + transition tests |
| thresholds policy-driven | `setThresholds` test |
| readings do not trigger unbounded telemetry | ring overflow test (1000 readings → history ≤ cap) |
| pressure drives P9 degradation | `degradationHook` + `DEGRADATION_LEVELS` |
| collector fails safely | throwing collector → UNKNOWN, no throw-out |
| low-resource environment test | critical flood under `historySize: 16` |
